# Temporary experiment-method issue list (delete before finishing)

- [ ] Binary classification endpoints are threshold-blind: `f1_positive`,
  precision, recall and balanced accuracy come from an implicit 0.5 cut. Under
  moderate imbalance a well-ranked model can look bad, and a threshold tuned
  on the evaluation split is currently invisible. Need an explicit threshold
  curve/selection helper (validation-only policy) plus record-level audit of
  `decision_threshold` / source.
- [ ] Classification records expose rank metrics but not calibration. Add
  Brier score and expected calibration error so a ranking gain is not confused
  with usable probabilities, and audit their ranges.
- [ ] A score column whose orientation is reversed (ROC-AUC below chance)
  silently produces a "bad model" instead of a labelling/positive-class error.
  Detect and surface it.
- [ ] `METRIC_POLICY` does not state the threshold convention or name
  calibration endpoints; extend the declared policy so the audit can enforce it.
- [ ] Add CPU tests and design-log entries for the new contracts; run the full
  zero-GPU suite after each change and commit immediately.
