# 算力规划：扩规模路线图与预算口径

本文件记录把本项目从「WikiText-103 小模型受控研究」推进到「主会长文所需
规模带」的路线图、算力预算口径与阶段判据，取代原 `算力申请.md`（申请表
正文不再入库，其核心内容已并入本文件）。文中所有数字均为**规划值**：
实验量值仍以零 GPU 报告构建器从落盘产物现算为准；预算以实测吞吐与
TimeGuard 计量校准后滚动修正。

## 1. 背景与目标

- 现状：全部面板在 WikiText-103（BPE-8k）+ d≤512/10L（`csa_dynamic`
  最大约 44M 参数）上完成；单次 40k 步长跑约 2.5 亿 token。统计协议
  （参数对齐、前缀不变性、配对符号翻转检验、零 GPU 重建）已在小规模
  验证。
- 目标：把结论推进到主流受控消融规模带——模型 0.14B–1.3B、token
  5B–60B、序列 8k 训练 / 64k 评测、真实内核吞吐实测、同类方法
  （NSA / MoBA）同场受控对比。
- 分工：现有 WikiText-103 面板保留为「机制层」（消融、探针、统计
  协议）；新算力全部投入「规模层」（大语料 + 大模型 + 内核 + 长上下文）。

## 2. 硬件与预算换算口径

| 口径 | 数值 |
|---|---|
| 额度锚点 | 8×H800×15 个月 ≈ 86,400 H800·卡时（隐含约 11.6 元/卡时） |
| 执行窗口（6 个月 × 8 卡） | 理论上限 34,560 卡时；按约 65% 有效利用率计约 22,000 卡时 |
| H800 bf16 峰值 | 约 989 TFLOPS/卡 |
| 优化后有效吞吐假设 | 稠密臂（SDPA/FlashAttention）350–450 TFLOPS；CSA/HCA 臂（Triton 内核）200–300 TFLOPS（20–30% MFU，保守取值） |
| 训练计算量 | FLOPs ≈ 6 × N_params × D_tokens；长序列臂另计注意力项（约 +30–50%） |

## 3. 关键前提：算子内核化（M0 的地位）

当前 CSA/HCA 臂为 eager PyTorch 实现，实测有效吞吐约 0.5 TFLOPS 量级
（d=256/6L/seq512/bs12，1500 步约 0.2–0.5 GPU·h），与 H800 峰值相差约
三个数量级；稠密臂走 SDPA 不受此限制。按 TimeGuard 标度外推
（`csa_dynamic` 臂，0.62B × 25B token 单次运行）：

| 实现 | 估算 |
|---|---|
| eager 外推 | 约 13–17 万 H800·卡时（单次运行即超全部额度，不可行） |
| Triton 内核（25% MFU） | 约 100–150 卡时 |

结论：**内核工程不是加分项，而是扩规模面板成立的前提**。M0 交付三个
核心算子的 Triton 融合内核（块压缩、索引 top-k 选择、稀疏注意力），并用
同种子、同数据的 kernel vs eager 全量对照验证数值一致性（统计不可
区分），内核变体标识进入 `CODE_SEMANTICS` 指纹。

## 4. 三档方案总览

| 档 | 规模阶梯 | 数据 / 长度 | 预算（H800·卡时） | 定位 |
|---|---|---|---:|---|

## 5. B 档规模阶梯与运行矩阵

参数量为 `exp_lib.SmallGPT` 实例化统计（32k 词表；S4 为解析外推）：

| 规模点 | 配置 | csa_dynamic 参数量 |
|---|---|---:|
| S1 | d=768 / 12L / 12H / dh=64 | 约 0.14B |
| S2 | d=1024 / 16L / 16H / dh=64 | 约 0.26B |
| S3 | d=1536 / 20L / 24H / dh=64 | 约 0.62B |
| S4（hero） | d=2048 / 24L / 32H / dh=64 | 约 1.3B |

- 变体臂：`full_matched`、`full_sw128_matched`、`csa_fixed`、
  `csa_dynamic`、`hybrid_dynamic` + 外部基线臂（NSA 复现；S2 起加
  MoBA 复现）。
- 种子策略（分层）：S1×4、S2×3、S3×2–3、hero×2；配对比较沿用现有
  配置指纹 + 符号翻转检验协议。
- 数据：FineWeb-Edu 高质量子集（约 15B token），自训 32k BPE 分词，
  `npy` 缓存 + SHA-256 指纹（沿用现有纪律）；保留 WikiText-103 PPL
  作为新旧面板桥接。
- 评测：FineWeb-Edu 留出集 PPL、RULER 子集 + needle 式检索（32k–64k）、
  KV 缓存与吞吐微基准、干扰注入探针迁移到 S2。

## 6. 里程碑与预算（6 个月，gate 制）

| 阶段 | 时间 | 内容 | 预算（H800·卡时） |
|---|---|---|---:|
| M0 | 第 1 个月 | Triton 内核三算子 + kernel/eager 数值对照 + FineWeb-Edu 语料与分词缓存 + DDP 化 + 吞吐校准 | 约 1,200 |
| M1 | 第 2 个月 | S1 参数对齐主面板 + NSA 复现臂（6 臂 × 4 种子 × 5B token） | 约 700 |
| M2 | 第 3–4 个月 | S2 主面板含 MoBA（7 臂 × 3 种子 × 12B）+ seq-8k 臂（4 臂 × 2 种子 × 4B）+ 32k/64k 评测 + top-k/压缩率扫描 + 机制探针迁移 | 约 1,700 |
| M3 | 第 5 个月 | S3 主面板（6 臂 × 2–3 种子 × 25B）+ hero 1.3B × 60B × 3 臂 × 2 种子（8 卡 DDP，单跑约 2.7 天） | 约 5,500 |
| M4 | 第 6 个月 | 补种子、统计冻结、零 GPU 报告重建、内核与产物开源、成稿投稿；rebuttal 复跑池 | 约 1,000–2,000 |
| 合计 | 6 个月 | — | 约 1.0–1.1 万（按 0.9–1.4 万区间规划） |

阶段判据：

- **G0（M0 出口）**：稀疏内核有效吞吐 ≥150 TFLOPS；kernel 与 eager 的
  同种子配对结果统计不可区分。
- **G1（M1 出口）**：小规模面板的效应方向在 0.14B 复现。
- **G2（M2 出口，最关键决策点）**：动态分块相对固定分块与稠密基线的
  差距随规模、训练量的趋势明确 → 决定 M3 投入与论文叙事（正结果与
  边界结果均按预注册判据成文）。

## 7. 执行与工程要点

- 8 卡双模排班：S1–S3 走 `CSA_PAR=auto` 一卡一实验（`par.py` 零改动；
  0.62B 的 AdamW 状态 + bf16 + 激活检查点单卡 80G 可容纳）；S3 加速与
  S4 hero 用 torchrun DDP。
- 数值纪律：kernel vs eager 对照跑进入统计协议；`CODE_SEMANTICS` 增加
  内核变体标识；换内核不改变结论需显式验证后方可冻结主表。
- 记账：TimeGuard 按 GPU·秒计量（并行按 GPU-秒总账），可按月导出
  使用报告；预算 gate 以 TimeGuard 状态为准。
- 开发省额度：内核开发与调试在自费 4090 上完成，集群额度只用于正式
  面板训练。
- 存储：语料缓存约 30GB；checkpoint 只留 final/best（沿用原子落盘
  规范），全程预留 2–4TB。
- 硬件口径：以 H800 卡时计价；TPU 不纳入（Triton 不可移植，移植成本
  大于收益）。

## 8. 扩展期权（判据触发，不计入核心承诺）

若 G2 通过且周期允许，第 7–15 个月追加 2B × 约 120B token 旗舰对照
（对齐 DeepSeek 稀疏注意力工作的受控消融规模口径），追加约 1.8–2.1 万
卡时。B + C 合计约 3 万卡时（等值约 35 万元），仍远低于额度上限——按
判据消耗，不为花完额度而花。

## 9. 风险与降级路径

- 内核延期 → 砍单顺序：MoBA 臂 → top-k 扫描密度 → S3 第三种子 →
  hero 降为 2 臂 × 1 种子 → 最后才动 S2 面板（S2 为不可砍核心）。
- kernel/eager 配对验证不通过 → 回退 eager 并重估预算（等效回到 A 档
  口径），同时排查数值漂移来源。
- 统计分辨率不足 → 优先在小规模补种子，而非扩大模型。
- 数据 / 分词变化 → 冻结分词器与语料指纹后再开 M1。
